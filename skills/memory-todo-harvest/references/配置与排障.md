# 配置与排障

按「现象 → 先查什么 → 怎么改」组织。左列是你看到的问题，右列是可以直接动手的处置。

---

## 一、扫描与发现

### 一条都没抽到

**先查**：`--dry-run` 输出的第一行「记忆文件：N 个」。

| N | 判断 | 处置 |
|---|---|---|
| 0 | 没扫到任何记忆文件 | 检查 `roots` 是否指向**工作区容器根**（不是某个项目目录）；检查记忆目录是否符合「目录名 + 父目录标记」双条件 |
| >0 但条目 0 | 扫到了文件，但里面没用待办信号 | 见「命中过少」 |

### 记忆文件扫不全

记忆目录的判定 = **目录名命中**（`memory` / `memories` / `memory-bank` / `journal` / `notes`）
**且父目录链里出现 agent 状态目录标记**。两个条件都要——只按目录名会把普通项目里
叫 `memory/` 的目录也纳进来。

自定义生态时改这两项：
```json
{ "memory_dir_names": ["memory", "memories", "journal"],
  "agent_state_dirs": [".workbuddy", ".claude", ".my-agent"] }
```

### 指令文件（AGENTS.md / CLAUDE.md）没被扫到

- `scan_instruction_files` 默认开；被关掉就不会扫
- 扫描有**深度上限**（默认 3 层），更深的目录里不放
- 文件名要在 `longterm_files` 名单里；新增文件名加进去

### 把依赖目录里的东西也扫进来了

`exclude_dirs` 里补上目录名（默认已含 `node_modules` / `.git` / `venv` / `dist` / `build` 等）。
如果某些路径永远不该扫，用 `exclude_path_frags` 按路径片段排除。

## 二、命中过多 / 过少

### 抽出上千条，淹没

**这是口径配错，不是算法问题。** 检查两处：

1. 是否把**普通日志/文档目录**也当成了记忆目录 —— 收紧 `memory_dir_names` 或加 `exclude_path_frags`
2. 是否有文件把**整节正文**都贡献成了待办 —— 见下一条

经验值：正常应该落在**几十条**量级。差一个数量级就是口径问题。

### 某个文件整节内容都被捞成待办

多半是**章节名以「待办」开头但在讲别的事**（例如一篇讲「待办清单怎么整理」的文档）。
待办章节判定必须严格：去掉括号补充后的核心词**等于**关键词，或只多出极短限定；
否则整节被逐条入账。

### 文档里的「写法示例」被当成真待办

文档在举例说明标记怎么写时，示例会被当成真待办。
**两个层次都要处理**：

- 源头：示例标记包进反引号 `` `## 待办` ``
- 归集侧：对「行内代码内的标记一律跳过」做兜底

### 写在行中间的待办漏掉

行内标记必须用**搜索**而不是**行首匹配**——后者只从行首试一次，
「……。**待办**：X」这类写法会永远漏掉。

### 指令文件里的清单没被收进来

`- [ ]` 是显式标记、零歧义，**应该在任何文件里都认**，
包括被当作「长期档案」的指令/规则文件。
如果实现里对「长期档案」一刀切只认行内标记，清单会整批漏掉。

## 三、归属与事由

### 一大批「未分类」

**先查项目台账，再怀疑算法**，顺序很重要。

| 检查 | 处置 |
|---|---|
| 项目台账是否覆盖了所有真实项目线 | 缺项就补；未分类不为 0 时，第一步永远是查台账 |
| 中文项目名是否写了 `keywords` | **必须写**。纯中文名无法按空格分词，目录兜底永远匹配不上 |
| `keywords` 是否写全 | 别名要全：产品名、简称、错误码、关键术语都算 |
| `container_dirs` 是否漏了 | 容器目录若没登记，会被当成项目，把所有匹配不上的条目吸走 |

### 一大半条目挤在同一个项目里

典型的**兜底筐**。检查 `<项目根>/.workbuddy/memory` 的**上级目录**是不是容器目录——
容器目录不是项目。登记进 `container_dirs` 后，算法会跳过目录兜底，
继续用「项目锚 / 文件主题」判断，判不出就诚实落「未分类」。

### 靠后的条目归属为空

记忆文件里同级标题更替（`## 项目A …` 之后紧跟 `## 17:37 · 第二轮联调`），
若实现按「同级标题即换段」清空上下文栈，后半段的项目归属会全丢。
应改用**项目锚**：只记「最近一次命中项目的标题」，同级更替**不清空**，
超过距离阈值（默认 400 行）才失效。

### 事由标签显示成「未完成 / 下一步 / 结果」

文档结构词被当成了上下文。这些是**章节骨架，不是项目**，
应在候选里过滤掉，再向上回溯一层。

### 事由标签过长、被截断成省略号

先做**结构性剥离**再判长度：剥前导时间戳、剥括号补充、剥破折号后缀、
优先取引号内容。长度封顶后按**词边界**切；展示侧用 CSS 省略号 + 悬停给完整值，
不要两层各自硬截断。

## 四、状态与判定

### 待办明明没做，却显示已完成

状态判定被**整行**污染了——整行常含描述**前文**的「已发布 / 已完成」。
状态判定只能作用于**待办正文**（标记之后的部分）。

### 勾了完成，重建产物后判定没了

判定只写在归集产物里。产物是派生物，回滚 / 还原 / 重建都会丢。
必须另存**独立判定档案**，并在每次归集时双向对齐：
产物里有人工标记而档案没有 → 补档；产物里已取消而档案还有 → 撤档。

### 取消勾选后又变回已完成

归档对齐逻辑**只看「谁标的」没看「标成什么」**。
补齐条件要同时满足「人工标记」且「状态为已完成」；
取消勾选时要能把档案里的记录撤销掉。

### 改了标题之后，之前的判定不认了

条目 id 由「文件路径 + 标题」派生，标题改一个字 id 就变。
用**分级模糊匹配**兜住：同一文件阈值 0.6、跨文件 0.85（先打 0.9 折），
相似度用 Jaccard（交集/并集），命中后把判定迁移到新 id。

### 首屏就冒出几百条候选

候选制**只应对增量生效**。首次全量直接转正，否则人工要点几百次。

## 五、页面

### 勾一条，整页重排、位置全丢

勾选回调里做了全量渲染。改为：只改该行样式 + 局部计数，顶部出
「已更新 N 条 + 刷新视图」，把重排时机交给用户。

### 展开分组后自动折回

折叠状态的**读点和写点用了不同的键**（读用短名、写用完整显示名）。
给容器加一个与显示名解耦的**稳定键**，读写统一走它。

### 改了函数但没生效

单文件页面里**同名函数定义两次**，后定义的会静默覆盖先定义的。
`grep -c` 只能告诉你「存在」，发现不了覆盖——要统计定义次数，必须全为 1。

### 批量操作误伤了手工标记

批量操作（如项目结项）要记**来源标记**，
反向操作**只回滚本次批量产生的那批**，不动用户单独勾的条目。

---

## 六、数据处理纪律

### 排查问题时不要把真实数据清掉

**正在使用的数据 = 生产数据。** 排查前先原样留底：

```bash
cp todos.json /tmp/todos.bak.json      # 改 → 验 → cp 回来
```

「清零 + 重跑」**不能**代替备份——用户的手工判定会跟着没。
