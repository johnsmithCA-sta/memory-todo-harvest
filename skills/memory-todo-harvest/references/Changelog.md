# 版本发布说明

## 1.3.1 版本发布（2026-09-30）

- 新增「路径根」归类信号：日志文件住在专属项目目录下时，以目录信号为准，避免条目被归到错误的项目。
- 优化条目切分：条目下方的缩进续行与补语行并入同一条，不再被拆成多条。
- 优化过滤：「详见 / 参见 / 另见 / 参阅」开头的句子不再被当作待办。

## 1.3.1 版本发布（2026-09-22）

- 修复：把已核销的待办**改写成结论句**后，完成状态会丢、条目重新冒出来当候选。
  根因是判定只认文字相似度，整句重写就会双双跌破阈值。新增第三条匹配通道
  ——「同一记忆文件 + 同行号 + 重叠率 ≥ 0.5」：记忆文件是追加式的，旧行不会移动，
  行号比标题稳得多；再叠加重叠率护栏，文件被大幅重排时也不会认错条目
- 已人工核销的条目不再进「新发现 · 待确认」（此前靠模糊/行号通道认回来时会重新落进候选区）
- `--selftest` 增加判定找回的用例，含 3 条反向例（同行号但内容不同 / 行号不同 / 无行号），
  反向例必须通过——避免通道变成「无脑命中」

## 1.3.0 版本发布（2026-09-16）

- 修复：待办正文里带否定或未定说法时，条目可能被误判成「已作废」而从清单上消失
  （例如「未搁置，继续跟进」「还没叫停」「暂不确定要不要做」「暂不适用该方案」）
- 新增状态判定自测（`--selftest`）：除了正向用例全过，还会把内部护栏临时关掉重跑一遍，
  必须出现失败才算通过——避免出现「自测永远通过、却测不出问题」的情况
- 明确行内标记的取词范围：标记之后的说明会被并进标题，**要让待办正文独占一行**，
  指针与上下文写在标记之前的加粗片段里
- 归档目录默认不再扫描：已经归档的条目不会再回到清单上

## 1.2.0 版本发布（2026-09-13）

- 新增「调整归属」：自动分错项目时，可在清单页面点条目右侧的「改组」手工纠正，
  写回后长期生效，不会被下次归集覆盖
- 自己写下的待办（`**待办**：` / `- [ ]`）直接进清单，不再逐条要求确认；
  只有从正文推断出来的条目才进「新发现 · 待确认」
- 修复正文较长的待办在清单上被截成半句的问题

## 1.1.2 版本发布（2026-09-13）

- 修复改过待办文字后，原来勾的完成状态会丢失、已忽略的条目又重新冒出来的问题
- 修复待办正文里写了目录路径时，条目可能被分到同名项目下的问题
- 整理使用说明：操作步骤与常见错误前置，判定原理收进参考文件

## 1.1.1 版本发布（2026-09-12）

- 安装后的目录更干净：说明文档统一收敛到技能主文档与参考文件
- 支持来源改用不带产品指向的表述，同一套配置在不同环境里都读得通

## 1.1.0 版本发布（2026-09-12）

- 新增可视化待办清单页面：归集后自动生成，按项目分组、可筛选、可折叠，离线可看、可直接分享
- 新增勾选写回：页面勾选后导出结果写回，完成状态会被记住；取消勾选也能撤销
- 新增「只要数据不要页面」的运行方式

## 1.0.1 版本发布（2026-09-11）

- 触发词改为用户会真实说出口的短短语（待办散落在各处、提取待办、统一清单、属于哪个项目…）
- 新增触发词评估集，用于校验触发精准度
- 「不触发」场景独立成节，与触发词分开

## 1.0.0 版本发布（2026-09-11）

首个版本。

- 归集口径：只认三类显式待办信号（待办章节 / 未勾选 checkbox / 行内待办句）；
  指令与规则文件只取显式标记，不把章节正文整段当待办
- 覆盖多家 agent 的记忆目录与项目指令文件，可混在一张清单里
- 归属补全：每条待办标出所属项目与事由；分不清归属的诚实留「未分类」，不硬塞
- 误收可撤回：机器新提名的条目先待确认，确认或忽略的判定另存、不随数据重建丢失
- 配置驱动，纯标准库单脚本，支持预览与抽样核准
