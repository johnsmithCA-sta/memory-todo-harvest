# 记忆待办归集（memory-todo-harvest）

把 agent 每天写下的**记忆流水**与**规则文件**，变成一份**能勾、能分组、能追**的待办清单。

## Goal（可验证输出物）

归集完成后默认产出三件套，落在 `todos.json` 同目录：

| 输出 | 是什么 | 验收 |
|---|---|---|
| **`todos.html`** | **可视化待办清单页面（默认产物）** | 双击可看；按项目分组、可筛选、可折叠、可勾选导出 |
| `todos.json` | 结构化待办清单 | 每条含标题、状态、来源文件、归属项目、事由标签 |
| `todo-state.json` | 人工判定档案 | 勾选/忽略的判定落在这里，与清单解耦，可单独备份 |

页面是**自包含**的：内联 CSS / JS，零外部依赖、不联网，可离线打开、可直接分享给别人看。

**勾选怎么落盘**：浏览器改不了磁盘文件，所以走两步——
页面里勾选 → 点「导出勾选结果」得到 `checked.json` →

```bash
python3 scripts/harvest.py --apply-checked ./checked.json
```

写回会同时更新清单与判定档案（勾选→完成；取消勾选→撤销人工完成），并自动重新生成页面。

## 什么时候用

- 记忆文件里写了不少「待办 / 下一步 / 未完成 / `- [ ]`」，但散在各项目、没人回头看
- 想给自己做一个本地待办面板，数据源就是自己（或 agent）写过的记忆文件
- 已经试过「把会话记录全导出当待办」——结论是淹没，需要收窄口径
- 待办抽出来了，但每条看不出**属于哪个项目、是为什么事留下的**

## 什么时候不用

- 记忆文件里几乎不写待办 —— 先改书写习惯（见「源头约定」），否则抽出来是空的
- 需要多人协作、派工、甘特图 —— 那是项目管理工具
- 想从**源码注释**里扫 `TODO:` —— 那是代码扫描器一类工具的活
- 已经在用笔记软件的任务体系，且任务都规范写成 checkbox —— 用其内建插件更顺
- 期待**自动判断待办是否已完成** —— 本技能明确不做，见「不该做的两件事」

## 不该做的两件事

**1. 不要把「会话活动记录」当待办归集。**
活动记录描述的是**已经发生的事**，天然绝大多数已完成。把它当待办，
真实待办会被淹没——活动记录与待办的数量级差可达 **50 倍**。
口径必须是「只归集被明确标记为待办的东西」。

**2. 不要用算法自动判定「已完成」。**
记忆文件是**只增不改的流水账**，做完通常不会回头改原条目，
所以最强的「同位置状态变更」信号天然不存在。
用「后续日志重述 / 产出物存在性 / 同段落痕迹」等旁证去猜，
召回率只有个位数百分比，而一旦猜错就**错误关闭真实待办**——比不判更糟。
根治办法在源头：完成就把 `- [ ]` 改成 `- [x]`。

## 支持的记忆来源

### 一、记忆目录（按天/按主题的流水与档案）

| 生态 | 典型路径 | 说明 |
|---|---|---|
| 通用 agent 工作区 | `<项目>/.workbuddy/memory/*.md` | 按天流水 + `MEMORY.md` 长期档案 |
| Claude Code 自动记忆 | `~/.claude/projects/<项目>/memory/*.md` | `MEMORY.md` 为索引，主题文件按需加载 |
| 记忆库模式 | `<项目>/memory-bank/*.md` | 长期项目记忆约定 |
| 其他 agent 状态目录 | `<项目>/.codex/` `.cursor/` `.serena/memories/` `.agents/` 等 | 同构目录，按名匹配 |

判定规则：**目录名命中（memory / memories / memory-bank / journal / notes）
且父目录链里出现 agent 状态目录标记**。两个条件都要——
否则普通项目里叫 `memory/` 的目录会被误纳。

### 二、指令 / 规则文件（长期档案）

| 生态 | 文件 |
|---|---|
| 跨工具标准 | `AGENTS.md`、`AGENTS.override.md` |
| Claude Code | `CLAUDE.md`、`CLAUDE.local.md` |
| Gemini CLI | `GEMINI.md` |
| Cursor | `.cursorrules`、`.cursor/rules/*.mdc` |
| GitHub Copilot | `.github/copilot-instructions.md`、`*.instructions.md` |
| Windsurf | `.windsurfrules`、`.windsurf/rules/*.md` |
| 其它 | `.clinerules`、`.roorules`、`CONVENTIONS.md`、`WARP.md`、`TODO.md` |

这些文件同时装着**规则正文**与**真正的待办清单**。因此统一按「长期档案」处理：
**只认显式待办信号**（未勾选 checkbox 与「待办：」标记行），
不把章节正文整段当待办。

> 两类来源都不限定具体产品：同一套配置可以同时收多个 agent 工作区、
> 各家自动记忆目录与项目里的指令文件，混在一张清单里。

## Steps

### 0. 生成配置

```bash
python3 scripts/harvest.py --init
```

产出 `harvest.config.json`。必填三项：`roots`（扫哪些目录）、
`projects`（项目台账，含 `keywords`）、`container_dirs`（容器目录名）。

### 1. 先看不写盘

```bash
python3 scripts/harvest.py --dry-run
```

会列出：扫到几个记忆文件、每个文件命中几条、总数、未分类数。
**这一步是门禁**：命中量应落在「几十条」量级；
若上千条，说明口径配错了（多半是把普通日志目录也纳进来了）。

### 2. 抽样核准

```bash
python3 scripts/harvest.py --dry-run --sample 60
```

逐条看命中的是不是真待办。**准确率低于 90% 就先调口径，不要往下走**——
后面所有环节都建立在这批条目上。

### 3. 正式写盘

```bash
python3 scripts/harvest.py
```

产出 `todos.json` + `todo-state.json`。**连跑两遍，输出应完全一致**（幂等）。

### 4. 看清单

归集时已自动生成 `todos.html`，直接双击打开。单独渲染：

```bash
python3 scripts/render_todos.py --data ./todos.json --out ./todos.html
```

只想要数据、不要页面：`python3 scripts/harvest.py --no-html`。
四条页面硬要求见「呈现要点」。

### 5. 勾完成并写回

```bash
# 页面里勾选 → 导出 checked.json → 写回
python3 scripts/harvest.py --apply-checked ./checked.json
```

写回后自动重新渲染页面。**判定档案会记住你的勾选，下次归集不会丢。**

### 6. 日常维护

- 新写的待办：重新跑一次脚本
- 勾完成 / 忽略：页面导出 + `--apply-checked`
- 项目结项：批量归档 + 保留可界定的反向操作

## 核心机制

### 一、三类待办信号

只有下面三类进清单，其余一律不进：

| 信号 | 形态 |
|---|---|
| 待办语义章节 | `## 待办` / `### 下一步` / `### 未完成` / `### 遗留项` …（章节内列表项逐条入账，标题只作「出处」） |
| 未勾选 checkbox | `- [ ] 要做的事`（`- [x]` 视为已完成） |
| 行内待办句 | `**待办**：…` / `剩余待办：…`（可写在行中间；带 ①②③ 编号的自动拆成多条） |

四条必须配的防护：

1. **行内标记用「搜索」而不是「行首匹配」** —— 否则写在行中间的标记永远漏掉
2. **状态只看待办正文，不看整行** —— 整行常含描述**前文**的「已发布 / 已完成」，会污染判定
3. **排除行内代码里的标记** —— 文档举例说明写法时，示例会被当成真待办捞走
4. **待办章节判定要严格** —— 章节名以「待办」开头但在讲别的事（如「待办清单整理」），
   不能算待办章节，否则整节被逐条捞走

外加：正文清洗（去 markdown 标记 / 前导时间戳 / 长度封顶）、**凭据掩码**、
**陈旧标记**（未完成超过 N 天的单独折叠，不混在当前待办里）。

### 二、防误收：三层兜底

机器抽取一定有错收与漏判。关键不是消灭错误，而是让错误**可发现、可撤回、可持久**。

**① 候选制** —— 机器**新**提名的待办先进「新发现 · 待确认」区，
人工确认才转正、忽略才进黑名单。首次全量不做候选（否则要手点几十上百条），**只对增量生效**。

**② 独立判定档案** —— 人的判定**不要只写在归集产物里**。
产物是派生物，随时可能被重建 / 回滚 / 还原备份，判定就丢了。
另存 `todo-state.json`，与产物解耦，单独可备份、可人工查看（纯 JSON，一行一条）。
判定优先级：**独立档案 > 产物内人工标记 > 日志信号 > 默认未完成**。

**③ 分级模糊匹配** —— 条目 id 由「文件路径 + 标题」派生，标题改一个字 id 就变、判定失效。用模糊匹配兜住，阈值必须分级：

| 范围 | 阈值 |
|---|---|
| 同一记忆文件 | 相似度 ≥ 0.6 |
| 跨文件 | ≥ 0.85（先打 0.9 折） |

用 **Jaccard 相似度**（交集/并集），不用重叠系数（交集/较小者）——
后者会让短标题对长标题虚高。命中后自动把判定迁移到新 id。
**取向：宁可不匹配（人工再勾一次），也不误匹配（错误关闭真实待办）。**

### 三、归属补全：项目锚定

条目归属按**加权打分、取最高分**：

| 信号 | 权重 | 来源 |
|---|---|---|
| 标题 | 6 | 待办正文 |
| 上下文 | 5 | 「待办：」之前的加粗片段 |
| **项目锚** | 5 | 向上回溯最近的「带项目名的章节标题」 |
| 文件主题 | 3 | 全文件出现最多的带项目名标题 |
| 目录 | 2 | 记忆目录的上级目录名 |

**项目锚**是核心：维护「最近一次命中项目的标题」，**同级标题更替时不清空**。
记忆文件里常见

```
## 项目A 需求梳理
### 下一步
   1. 联调前补错误码表        ← 归属正常
## 17:37-18:01 · 第二轮联调     ← 同级新标题，不含项目名
### 下一步
   2. 生产前换掉临时存储       ← 靠锚回溯才不丢归属
```

若按「同级标题即换段」清空，第 2 条往上的上下文就全丢了。

两个必须避开的错误：

1. **容器目录不是项目** —— `工作区/` 这类只是「放项目的文件夹」。
   把它当项目兜底，匹配不上的条目会全塞进同一个筐，页面上一大半看不出归属。
2. **中文项目名必须在配置里写 `keywords`** —— 纯中文名无法按空格分词，
   目录兜底永远匹配不上，条目会大批落「未分类」。
   别名要写全：产品名、简称、错误码、关键术语都算。

**事由标签要净化**才不会「看不懂」：剥掉前导时间戳、括号补充、破折号后缀，
优先取引号内容，再把文档结构词（`未完成 / 下一步 / 待办 / 结果 / 产出 / 结论 / 验收 / 备份 / 归档`）
一律排除——它们是**文档骨架，不是项目**。

### 四、呈现要点

- **按项目分组**，组头即项目卡（完成比 + 进度 / 下一步 / 卡点）
- **非项目分组里的条目要带项目角标** —— 这些组里条目来自多个项目，光看标题分不清归属
- **勾选不要触发整页重排** —— 勾一条就跳组重排会让视线与滚动位置全丢，
  批量操作直接不可用。改为原地生效 + 顶部提示「已更新 N 条 + 刷新视图」
- **折叠状态键与显示名解耦** —— 用稳定键读写；读写键不一致的症状是
  「展开后只要重渲染一次就折回去」
- **批量破坏性操作三件套** —— 二次确认说明影响条数、每条判定记来源标记、
  提供只回滚「本次批量产生」的反向操作

## 配置项

| 键 | 作用 | 建议 |
|---|---|---|
| `roots` | 扫描根目录（可多个） | 工作区容器根 + agent 家目录 |
| `projects` | 项目台账：`id` / `name` / `keywords` | **中文项目名必须写 keywords** |
| `container_dirs` | 容器目录名（不是项目本身） | 写上放项目的上层目录 |
| `dir_project_map` | 目录名 → 项目名 | 目录名与项目名不一致时补 |
| `memory_dir_names` | 记忆目录名 | 默认 memory / memories / memory-bank / journal / notes |
| `agent_state_dirs` | agent 状态目录标记 | 默认覆盖主流 agent |
| `longterm_files` | 按「长期档案」处理的文件名 | 默认含各家指令文件 |
| `scan_instruction_files` | 是否扫指令/规则文件 | 默认开 |
| `stale_days` | 未完成超过几天算「历史遗留」 | 默认 14 |
| `per_file_cap` | 单文件条目上限 | 默认 100（防御性） |

## Verification Checklist

- [ ] `--dry-run` 能列出记忆文件，且命中量落在几十条量级
- [ ] 抽样 60 条，人工判断准确率 ≥ 90%
- [ ] 连跑两遍输出完全一致（幂等）
- [ ] 未分类接近 0；不为 0 时先查项目台账是否缺项
- [ ] 抽查 5 条，项目归属事由标签可读
- [ ] 页面：零控制台错误；折叠组重渲染两次仍保持展开；勾选不重排
- [ ] 判定档案：手动勾一条 → 清空产物重跑 → 判定仍在
- [ ] 凭据：清单里不含密码 / token 明文

## 已知误报与常见疑问

| 现象 | 原因 / 处理 |
|---|---|
| 抽出来是空的 | 记忆文件里没用三类信号；或 `roots` 配错。先跑 `--dry-run` 看扫到几个文件 |
| 抽出一堆垃圾、整节内容都进来了 | 待办章节判定过宽；或文档里写了裸的写法示例（示例应包在反引号里） |
| 大批条目「未分类」 | 项目台账 `keywords` 没写全；或容器目录被当成了项目 |
| 事由标签显示成「未完成 / 下一步」 | 结构词没过滤；这类词是文档骨架，不是项目名 |
| 勾选后取消，刷新又变回已完成 | 归档对齐逻辑只看「谁标的」没看「标成什么」——取消也要同步撤销档案 |
| 展开分组后自动折回 | 折叠状态键读写用了不同的名字 |
| 为什么不做「自动判断已完成」 | 见「不该做的两件事」第 2 条；错误关闭真实待办的代价高于收益 |
| 「未分类」为什么要留着不兜底 | 错误的归属比诚实的未分类更糟——它会让用户误以为已经整理好了 |

## 使用示例

> 用户：「我的 agent 记忆文件里记了一堆待办，散在各项目，想看一个统一清单。」

1. `harvest.py --init` → 填 `roots` 指向工作区容器根，`projects` 写项目名 + `keywords`，
   `container_dirs` 写上放项目的上层目录
2. `harvest.py --dry-run` → 确认命中量在几十条、不是上千条
3. `harvest.py --dry-run --sample 60` → 逐条核准，准确率 ≥ 90% 才继续
4. `harvest.py` → 写盘；再跑一遍确认幂等
5. 打开自动生成的 `todos.html` 看清单
6. 日常：新内容重跑脚本；页面勾选 → 导出 → `--apply-checked` 写回
