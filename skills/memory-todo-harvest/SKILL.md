# 记忆待办归集（memory-todo-harvest）

把 agent 每天写下的**记忆流水**与**规则文件**，变成一份**能勾、能分组、能追**的本地待办清单。

## 定位

记忆文件按天写、按项目散，写下的「待办 / 下一步 / 未完成」没人回头看。本技能把这些文件扫一遍，
只挑出**被明确标记为待办**的条目，按项目分好组，落成一份可勾选的可视化页面 + 结构化数据。

判定权留给人、不回写记忆文件、不联网——所以它跑得再勤也不会污染你的原始记录。

## 何时用（适用 / 不适用）

**用它**
- 记忆文件里写了不少「待办 / 下一步 / 未完成 / `- [ ]`」，散在各项目、没人回头看
- 想给自己做一个本地待办面板，数据源就是自己（或 agent）写过的记忆文件
- 待办抽出来了，但每条看不出**属于哪个项目、是为什么事留下的**

**不用它**
- 记忆文件里几乎不写待办——先改书写习惯（完成就把 `- [ ]` 改成 `- [x]`），否则抽出来是空的
- 需要多人协作、派工、甘特图——那是项目管理工具
- 想从**源码注释**里扫 `TODO:`——那是代码扫描器的活
- 已经在用笔记软件的任务体系，且任务都规范写成 checkbox——用其内建插件更顺

## 触发词

- 待办散落在各处 / 记了但看不到 / 提取待办 / 归集待办 / 整理待办
- 统一清单 / 待办清单 / 个人待办 / 待办面板
- 记忆文件 / 记忆目录 / 规则文件 / 日志里 / 会话记录 / 全是噪音
- 属于哪个项目 / 项目归属 / 看不出归属
- 勾选之后 / 重建数据 / 判定丢失 / 状态怕丢
- extract todos / harvest todos / agent memory / unified todo list

**不触发**：从源码注释扫 TODO（用代码扫描器）· 多人派工（用项目管理工具）·
笔记软件内建任务（用其插件）· 记忆文件的摘要与改写（用文档处理类技能）

## Goal（可验证输出物）

归集完成后默认产出三件套，落在 `todos.json` 同目录：

| 输出 | 是什么 | 验收 |
|---|---|---|
| **`todos.html`** | 可视化待办清单页面（默认产物） | 双击可看；按项目分组、可筛选、可折叠、可勾选导出 |
| `todos.json` | 结构化待办清单 | 每条含标题、状态、来源文件、归属项目、事由标签 |
| `todo-state.json` | 人工判定档案 | 勾选 / 忽略的判定落在这里，与清单解耦、可单独备份 |

页面是**自包含**的：内联 CSS / JS，零外部依赖、不联网，可离线打开、可直接分享给别人看。

## Inputs（必填 / 可选）

**必填**
- `roots`：扫描根目录，可多个。一般填「放项目的容器根目录」+ agent 家目录

**可选（都有默认值）**
- `projects`：项目台账（`id` / `name` / `keywords`）。**中文项目名必须写 `keywords`**
- `container_dirs`：容器目录名——它们只是「放项目的文件夹」，不是项目本身
- `dir_project_map`：目录名 → 项目名（目录名与项目名不一致时补）
- `stale_days`（默认 14）· `per_file_cap`（默认 100）· `scan_instruction_files`（默认开）

### 支持的来源

| 类型 | 覆盖 |
|---|---|
| 记忆目录 | `memory` / `memories` / `memory-bank` / `journal` / `notes` 等目录名，且父目录链里出现 agent 状态目录标记——两个条件都要，否则普通项目里叫 `memory/` 的目录会被误纳 |
| 指令 / 规则文件 | `AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、`.cursorrules`、`.cursor/rules/*.mdc`、`copilot-instructions.md`、`.windsurfrules`、`.clinerules`、`.roorules`、`CONVENTIONS.md`、`WARP.md`、`TODO.md` 等 |

指令 / 规则文件同时装着**规则正文**与**真正的待办清单**，所以统一按「长期档案」处理：
只认显式待办信号，不把章节正文整段当待办。两类来源都不限定具体产品——
同一套配置可以同时收多个 agent 工作区，混在一张清单里。

## Constraints（不做什么 + 质量门槛 + 逃逸条款）

**不处理**
- **不把「会话活动记录」当待办**——活动记录描述的是**已经发生的事**，天然绝大多数已完成；
  拿它当待办，真实待办会被淹没（量级差可达两个数量级）。口径是「只归集被明确标记为待办的东西」
- **不用算法自动判定「已完成」**——记忆文件是只增不改的流水账，做完通常不会回头改原条目，
  靠旁证去猜的可靠召回率只有个位数百分比，而一旦猜错就是**错误关闭真实待办**，比不判更糟。
  根治办法在源头：完成就把 `- [ ]` 改成 `- [x]`
- **不自动回写记忆文件**——脚本改动有覆盖人工校改的风险，而并行会话写同一文件还可能静默覆盖
- **不设兜底项目**——给个「其他」筐看起来能让未分类归零，实际是把错误藏起来；
  错误的归属比诚实的未分类更糟

**质量门槛**
- 抽样核准准确率 ≥ 90% 才写盘；连跑两遍输出必须完全一致（幂等）
- 清单里不得出现密码 / token 明文（凭据自动掩码）
- 未分类数不为 0 时，先查项目台账有没有缺项，再怀疑算法

**逃逸条款**：本技能的「不处理」与用户明确意图冲突时，优先保障用户的数据与意图，
并显式说明偏离理由与替代动作——不静默偏离。

## Steps

### 0. 生成配置

```bash
python3 scripts/harvest.py --init
```

产出 `harvest.config.json`。必填三项：`roots`（扫哪些目录）、`projects`（项目台账，含 `keywords`）、
`container_dirs`（容器目录名）。

### 1. 先看不写盘（这一步是门禁）

```bash
python3 scripts/harvest.py --dry-run
```

会列出：扫到几个记忆文件、每个文件命中几条、总数、未分类数。
**命中量应落在「几十条」量级**；若上千条，说明口径配错了（多半把普通日志目录也纳了进来）。

### 2. 抽样核准

```bash
python3 scripts/harvest.py --dry-run --sample 60
```

逐条看命中的是不是真待办。**准确率低于 90% 就先调口径，不要往下走**——
后面所有环节都建立在这批条目上。

### 3. 正式写盘

```bash
python3 scripts/harvest.py
```

产出 `todos.json` + `todo-state.json`。**连跑两遍，输出应完全一致**（幂等）。

### 4. 看清单

归集时已自动生成 `todos.html`，直接双击打开。单独渲染：

```bash
python3 scripts/render_todos.py --data ./todos.json --out ./todos.html
```

只想要数据、不要页面：`python3 scripts/harvest.py --no-html`。

### 5. 勾完成后写回

浏览器改不了磁盘文件，所以走两步——页面里勾选 → 点「导出勾选结果」得到 `checked.json`：

```bash
python3 scripts/harvest.py --apply-checked ./checked.json
```

写回会同时更新清单与判定档案（勾选 → 完成；取消勾选 → 撤销人工完成），并自动重新渲染页面。

### 6. 日常维护

新写了待办 → 重跑一次脚本；勾完成 / 忽略 → 页面导出 + `--apply-checked`。

## Verification Checklist

- [ ] `--dry-run` 能列出记忆文件，命中量在几十条量级
- [ ] 抽样 60 条，人工判断准确率 ≥ 90%
- [ ] 连跑两遍输出完全一致（幂等）
- [ ] 未分类接近 0；不为 0 时先查项目台账
- [ ] 抽查 5 条，项目归属与事由标签可读
- [ ] 页面零控制台错误；折叠组重渲染两次仍保持展开；勾选不触发整页重排
- [ ] 改过某条待办的文字后重跑，这条的勾选仍在（判定不丢）
- [ ] 清单里不含密码 / token 明文

## 使用示例

> 用户：「我的 agent 记忆文件里记了一堆待办，散在各项目，想看一个统一清单。」

1. `harvest.py --init` → `roots` 指向工作区容器根，`projects` 写项目名 + `keywords`，
   `container_dirs` 写上放项目的上层目录
2. `harvest.py --dry-run` → 确认命中量在几十条、不是上千条
3. `harvest.py --dry-run --sample 60` → 逐条核准，准确率 ≥ 90% 才继续
4. `harvest.py` → 写盘；再跑一遍确认幂等
5. 打开自动生成的 `todos.html` 看清单
6. 日常：新内容重跑脚本；页面勾选 → 导出 → `--apply-checked` 写回
7. 之后又改写过记忆文件里某条待办的文字 → 重跑，这条的勾选还在

## 常见错误

**抽出来是空的**
- 症状：清单 0 条，或只有零星几条
- 原因：记忆文件里没用三类待办信号；或 `roots` 配错，压根没扫到文件
- 修复：先跑 `--dry-run` 看扫到几个文件——文件数目不对就调 `roots`；文件对但没条目，是书写习惯问题

**整节内容都被捞进来了**
- 症状：清单里出现成段的叙述句，而不是待办
- 原因：待办章节判定过宽；或文档里写了**裸的**待办写法示例（示例没包在反引号里）
- 修复：把示例包进反引号；检查有没有「待办清单整理」这类以「待办」开头却在讲别的事的章节名

**大批条目「未分类」**
- 症状：页面上一大半条目没有项目归属
- 原因：项目台账 `keywords` 没写全（中文项目名无法按空格分词）；或容器目录被当成了项目
- 修复：给每个项目补齐别名（产品名、简称、错误码、关键术语）；把放项目的上层目录写进 `container_dirs`

**条目被分到了不相干的项目**
- 症状：某条待办出现在一个跟它无关的项目分组里
- 原因：正文里的**路径片段**（如 `~/.xxx/skills/foo`）撞上了另一个项目的名字
- 修复：匹配前路径 / 点文件片段会被剥离；仍出现就把撞名的项目关键词改得更具体

**勾过的条目过一阵又变回未完成**
- 症状：明明勾过，重跑后又变成待办
- 原因：那条待办的**文字被改写过**，条目 id 随之变化，旧判定一时对不上
- 修复：一般改字不会丢判定（两条匹配通道详见 `references/口径说明.md` §十一）；
  整句重写超出识别范围时，人工再勾一次即可

**事由标签显示成「未完成 / 下一步」**
- 症状：条目的「事由」徽章是没有信息量的结构词
- 原因：结构词过滤没生效
- 修复：见 `references/口径说明.md` §十二

**展开分组后自动折回**
- 症状：点开一个分组，勾一条又折回去了
- 原因：折叠状态的读写用了两个不同的键名（读短键、写全名）
- 修复：给容器加一个与显示名解耦的稳定键，读写统一走它
